# Deployment Guide: Ubuntu (WSL2 or Native)

This guide provides the steps to deploy the `cob-agent-review-services-app` on an Ubuntu environment using **Kind** (Kubernetes in Docker). It incorporates fixes for common issues like PostgreSQL volume compatibility and missing Ingress rules.

## 1. Install Prerequisites

Run these commands to install the necessary tools:

```bash
# Update system
sudo apt-get update && sudo apt-get upgrade -y

# Install Docker
sudo apt-get install docker.io -y
sudo usermod -aG docker $USER
# NOTE: Restart your terminal or logout/login after this step.

# Install Kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl

# Install Kind (Kubernetes in Docker)
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.23.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind
```

## 2. Create the Kubernetes Cluster

Create a local cluster using Kind:

```bash
kind create cluster
```

## 3. Prepare the Images

Load the application images from your local Docker into the Kind cluster:

```bash
# Pull the images to your local Docker first
docker login https://dist.axonfintech.io
docker pull dist.axonfintech.io/cob-agent-review-service:1.4.1
docker pull dist.axonfintech.io/cob-agent-review-services-app:1.4.2

# Load them into Kind
kind load docker-image dist.axonfintech.io/cob-agent-review-service:1.4.1
kind load docker-image dist.axonfintech.io/cob-agent-review-services-app:1.4.2
```

## 4. Configure Hosts File

Add the local domain to your `/etc/hosts` so your browser can resolve the name:

```bash
echo "127.0.0.1 cob-agent-review-services-app.local" | sudo tee -a /etc/hosts
```

_Note: If you are using WSL2, you must also add this line to your Windows hosts file at `C:\Windows\System32\drivers\etc\hosts`._

## 5. Deploy the Application

Follow these steps to install and apply necessary fixes:

### 5.0 Clean up previous deployments (Optional)

If you need to redeploy from scratch, uninstall the existing deployment first:

```bash
./install.sh --uninstall
```

### 5.1 Run the Installer

Run the installation script. If you are deploying locally for testing and want a fresh PostgreSQL database spun up inside the cluster, append the `--db` flag:

```bash
./install.sh --db
```

> [!NOTE]
> For a **Production** environment where you connect to an external database, simply run `./install.sh` without the `--db` flag.

### 5.2 Apply Application Properties

Apply the ConfigMap and Secret containing the application properties:

```bash
kubectl apply -f config/cob-agent-review-services-app-properties-configmap.yaml
kubectl apply -f config/cob-agent-review-services-app-properties-secret.yaml
```

### 5.3 Fix Database Volume Path (Local `--db` only)

> [!NOTE]
> Skip this step if you are deploying to Production and did not use the `--db` flag.

If you deployed the local database, newer PostgreSQL images require a different mount path.

1. Open `sample/cob-agent-review-services-app-kubernetes-database.yaml`.
2. Change `mountPath: /var/lib/postgresql/data` to `mountPath: /var/lib/postgresql`.
3. Apply the change:

```bash
kubectl apply -f sample/cob-agent-review-services-app-kubernetes-database.yaml
```

### 5.4 Fix Ingress Rules

Ensure your `cob-agent-review-services-app-kubernetes.yaml` file includes paths for `/`, `/auth`, and `/api/q/health`.

```bash
kubectl apply -f cob-agent-review-services-app-kubernetes.yaml
```

### 5.5 Restart the Service

Force the application to pick up the new configuration:

```bash
kubectl rollout restart deployment/cob-agent-review-service -n com-axonfintech-cob
```

## 6. Access the Application

Expose the Ingress controller to your local machine on port 8088:

```bash
# Run this in a dedicated terminal
kubectl port-forward -n com-axonfintech-cob service/ingress-nginx-controller 8088:80
```

You can now access the app at:

- **Main App:** [http://cob-agent-review-services-app.local:8088/](http://cob-agent-review-services-app.local:8088/)
- **Admin Console:** [http://cob-agent-review-services-app.local:8088/auth/admin/](http://cob-agent-review-services-app.local:8088/auth/admin/)

## 7. Verify the Application

Once the application is running, verify it is healthy and accessible.

### 7.1 Verify Service Logs

The application is powered by Quarkus. Check its logs to confirm it has started successfully:

```bash
kubectl logs deployment/cob-agent-review-service -n com-axonfintech-cob
```

You should see an output similar to this:

```text
io.quarkus | cob-agent-review-service 1.4.1 on JVM (powered by Quarkus 3.20.0) started in 10.311s. Listening on: http://0.0.0.0:8080
io.quarkus | Profile prod activated.
```

### 7.2 Verify Application Access (cURL)

In the Kubernetes setup, the API endpoints are nested under `/api/agent-review`. With the Ingress port-forwarded to `8088` (as done in Step 6), you can verify the tasks endpoint using cURL:

```bash
curl -i -u "export-user:1234" --basic -H "Host: cob-agent-review-services-app.local" http://127.0.0.1:8088/api/agent-review/tasks
```

If successful, it will return an `HTTP/1.1 200 OK` response with the tasks array (e.g., `[]`).

### 7.3 Verify Webhook Callback (cURL)

To simulate a third-party service (like Fidentity) sending a POST callback to your application, use the following cURL command.

> [!IMPORTANT]
>
> - You **must** include `-H "Host: cob-agent-review-services-app.local"` so Nginx routes the request properly.
> - You **must** provide the Basic Auth credentials using `-u`. The password provided here acts as the "key" and must match the base64-encoded "lock" you configured in `cob-agent-review-services-app-properties-secret.yaml` (`quarkus.security.users.embedded.users.fidentity`).
> - We use the `-i` flag so you can see the empty HTTP response headers.

```bash
curl -i -X 'POST' \
  'http://127.0.0.1:8088/api/agent-review' \
  -H 'Host: cob-agent-review-services-app.local' \
  -u 'fidentity:eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJuYW1lIjoiR3Jhdml0eVQifQ.bfCXqWflnHYuSJNqNoHmBU5tNzMVadSnT3FANjNoXiY' \
  -H 'accept: */*' \
  -H 'Content-Type: application/json' \
  -d '{
  "reviewUrl": "https://test.server.ch/dashboard/process/as34-33fds232-adsdsd232-sdsd34/review",
  "state": "review-pending",
  "extId": "as34-33fds232-adsdsd232-sdsd34"
}'
```

If successful, the server will process the request and return an **empty body** with an `HTTP/1.1 201 Created` or `HTTP/1.1 204 No Content` status.
