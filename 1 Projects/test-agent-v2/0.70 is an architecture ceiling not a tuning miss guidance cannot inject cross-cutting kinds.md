# 0.70 is an architecture ceiling not a tuning miss: guidance cannot inject cross-cutting kinds

CEILING (LUZ-158390 push to 0.70): after the dedup fix lifted the assured score 0.58->0.62, further pushing (TPD_DEDUP_THRESHOLD 0.90 + coverage guidance) PLATEAUED at 0.62 — 0.70 is NOT reachable by config/guidance tuning. TWO architectural reasons: (1) the implement `guidance`/reflection steer CANNOT inject cross-cutting test kinds (zip-bomb, symlink, CP437/NFD i18n, pool-N concurrency, size-boundary trio). Generation is PER-PACK-UNIT (each batch generates kinds for a pack NODE via focus_units); cross-cutting security/i18n/concurrency scenarios are not tied to any node, so a text steer does not produce them — and attempting all kinds x all units overruns max_tokens and silently truncates the extras (known generator gotcha). Round-1 critique came back IDENTICAL despite explicit guidance = proof the steer did not change generation. (2) the single-cosine dedup threshold is a precision/recall TRADEOFF: 0.86 over-merges distinct security cases (coverage 24%->18%), 0.90 under-merges so near-dups survive and round 2 regressed 0.62->0.58. REAL PATH TO 0.70 (code, not tuning): a dedicated cross-cutting-kind generation pass (generate security/i18n/concurrency scenarios from the PLAN test_kinds independently of pack nodes, so they are not truncated) + a smarter dedup (behaviour-key + citation-aware, not one cosine cut). LESSON: know when a metric plateau is an ARCHITECTURE ceiling vs a tuning miss — stop the tuning loop once the same critique repeats. The dedup fix (0.62, triplication gone, 52 tests pass) is the shippable win; 0.70 is a separate scoped task.
